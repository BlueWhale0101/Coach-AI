# Codex Handoff — Object Registry + Tasks V0

## Goal

Implement the first Assistant.AI vertical slice: Object Registry + Tasks V0 + automated tests. Do not build UI.

Read before changing code:
1. assistant/Architecture.md
2. assistant/DecisionLog.md
3. assistant/modules/Tasks.md
4. Existing Coach Architecture.md and Interfaces.md only to understand protected boundaries and established implementation patterns.

## Hard boundaries

- Do not modify existing Coach database tables or their semantics.
- Do not change existing Coach Edge Function contracts or actions.yaml.
- Do not refactor Coach code as part of this task.
- Assistant objects may live in the same Supabase project/public schema, using assistant_ names.
- Preserve the module boundary: callers must not need to manually create assistant_objects rows.
- Do not add speculative modules or fields.

## Required implementation

1. Add a Supabase migration creating assistant_objects.
   - id UUID primary key, generated by database.
   - object_type text not null.
   - created_at timestamptz not null default now().
   - Keep this table minimal.
   - V0 must support object_type=task and prevent obviously invalid/empty type values. Choose a simple enforcement approach that will not require unrelated module schema migrations merely to add a future object type; document the choice.

2. Add assistant_tasks according to assistant/modules/Tasks.md.
   - FK object_id -> assistant_objects(id).
   - Enforce lifecycle/timestamp and time-window invariants with DB constraints where practical.
   - Add only indexes justified by V0 query operations.

3. Implement the Tasks module API/Edge Functions needed for:
   - create_task
   - update_task
   - complete_task
   - cancel_task
   - get_task
   - list_tasks
   - search_tasks

   Follow existing Coach conventions where useful (authentication, validation, safe errors, stable response envelope, pagination), while keeping Assistant contracts separate.

4. Ensure create_task creates assistant_objects + assistant_tasks atomically. Prefer a database function/RPC or another straightforward transaction boundary rather than compensating writes.

5. Ensure deletion, if implemented internally, cannot leave orphan registry/domain rows. Public task deletion is not required for V0.

6. Add automated tests covering at least:
   - successful creation and durable object identity;
   - invalid status/priority;
   - completed/cancelled timestamp invariants;
   - invalid not_before > due_at;
   - completion and cancellation transitions;
   - attempted invalid terminal transition;
   - get/list pagination and filters;
   - text search;
   - registry/task atomicity or failure behavior;
   - existing Coach interfaces remain untouched.

## Interface design expectations

Use capability-oriented operations, not a generic unrestricted CRUD endpoint.

update_task should permit only task-owned mutable fields. Prefer complete_task and cancel_task for terminal lifecycle transitions rather than accepting arbitrary status changes through update_task.

Return stable machine-readable error codes and safe human-readable messages.

All list/search operations must be bounded and paginated.

## Documentation deliverables

Update/add documentation sufficient for another implementation agent to understand:
- actual deployed schema;
- Tasks API request/response contracts;
- validation and state-transition rules;
- any implementation decision that differs from the proposed contract.

Do not rewrite the accepted architectural decisions merely to fit an implementation convenience. If a conflict is discovered, stop and document it for review.

## Completion gate

This package is complete when:
- migrations apply cleanly to a development/test environment;
- Tasks operations work through their public module interface;
- tests pass;
- existing Coach behavior/contracts are unchanged;
- no UI has been introduced;
- the final report lists files changed, tests run/results, migrations added, and any unresolved questions.

Do not deploy to the production Supabase project as part of this task unless explicitly instructed.
